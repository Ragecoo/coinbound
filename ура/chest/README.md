# Indigo Chest — инструкция для интеграции в игру

## Содержимое
- `spritesheet-original.png`: исходное изображение 1448×1086, прозрачный PNG.
- `spritesheet-32x48.png`: атлас 256×192, 8 столбцов × 4 строки, ячейка 32×48.
- `frames-original/{south,north,east,west}/`: 32 отдельных исходных кадра.
- `frames-32x48/{south,north,east,west}/`: те же кадры, приведённые к 32×48. Для обычного импорта используйте этот набор.

## Направления
Направление обозначает сторону, в которую обращена передняя стенка с замком, а не положение камеры.

| Строка атласа (с нуля) | Папка | Передняя сторона |
|---|---|---|
| 0 | south | Вниз экрана |
| 1 | north | Вверх экрана |
| 2 | east | Вправо экрана |
| 3 | west | Влево экрана |

Камера смотрит сверху под углом. Для north видна внешняя сторона поднятой крышки, перекрывающая внутренность. Не подменяйте north отражением south. Используйте готовые изображения каждого направления.

## Кадры и анимации
Столбцы идут слева направо. Номера совпадают с префиксами файлов.

| Кадр | Состояние |
|---|---|
| 00 | Закрыт |
| 01 | Начало открывания |
| 02 | Промежуточное открывание |
| 03 | Полностью открыт |
| 04 | Удержание открытого состояния |
| 05 | Начало закрывания |
| 06 | Промежуточное закрывание |
| 07 | Закрыт |

- Idle closed: 00, без проигрывания.
- Opening: 00 → 01 → 02 → 03, однократно; затем удерживать 03 или 04.
- Idle open: 04, без проигрывания.
- Closing: 04 → 05 → 06 → 07, однократно; затем перейти на 00.
- Весь ряд 00–07 — демонстрационный цикл, а не зацикленный idle.
- Начальная рекомендация: 100–140 мс на кадр; это настройка игры, в PNG таймингов нет.

## Правила размещения текстур
1. Размер напольного тайла — 32×32. Размер прямоугольника каждого кадра — 32×48; он включает прозрачное поле. Не растягивать видимую часть сундука до размера всей ячейки: уменьшенный сундук сделан намеренно.
2. Использовать одинаковый pivot для всех кадров и направлений: рекомендуемая исходная точка — нижний центр (16,48). Привязать её к нижнему центру занятого напольного тайла. При необходимости подправить общий вертикальный offset всего объекта после проверки в игре; не менять offset отдельно для каждого кадра.
3. Верхние 16 пикселей кадра могут заходить на область тайла выше. Не обрезать изображение по размеру напольного тайла.
4. Не обрезать кадры по видимым пикселям независимо друг от друга: это меняет отступы и вызывает скачки. Если упаковщик удаляет прозрачные поля, он обязан сохранять исходный размер и смещение каждого кадра.
5. При чтении нормализованного атласа прямоугольник кадра: x = column * 32, y = row * 48, width = 32, height = 48. Начало координат — левый верхний угол. Между ячейками нет дополнительных полей.
6. Фильтрация — nearest/point, без сглаживания и mipmaps. Отображать в целочисленном масштабе. Сохранять прозрачность PNG; чёрный фон не добавлять. При повторной упаковке можно использовать padding/extrusion для предотвращения попадания соседних текстур.
7. Порядок отрисовки определять по точке опоры на земле, а не верхней границе крышки. Коллизию задавать отдельно вокруг основания; движение крышки не должно менять коллизию или положение объекта.
8. Хранить направление и состояние независимо: смена направления выбирает другую папку, сохраняя текущую фазу анимации.

## Ограничения и проверка
Исходник создан генерацией изображений, поэтому это не вручную выверенный пиксельный атлас. Его размеры не равны 256×192. Нарезка выполнена по равномерной сетке 8×4: x = round(column * 1448 / 8), y = round(row * 1086 / 4). Исходные кадры имеют ширину 181 и высоту 271 или 272 пикселя. Не режьте исходный PNG непосредственно на 32×48.

Версии 32×48 уменьшены nearest-neighbor с сохранением полного прямоугольника ячейки; мелкие детали при уменьшении могут теряться. Отступы, неподвижность основания и отсутствие визуального дрожания необходимо проверить в игровом масштабе. Автоматическая нарезка не исправляет возможные различия формы между сгенерированными кадрами. При корректировке сохраняйте единую сетку, размеры, точку опоры и направление петель.
