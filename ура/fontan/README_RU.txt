COINBOUND — ПИКСЕЛЬНАЯ АНИМАЦИЯ ФОНТАНА

24 кадра, 12 кадров/с, цикл ровно 2 секунды.
Каждый игровой кадр — исходные 120×120 пикселей, прозрачный PNG.
Форма, ракурс, положение, прозрачные поля и каменные части сохранены. Меняются только пиксели воды в заданной маске.
Все RGBA-цвета игровых PNG взяты из исходного спрайта. Нет сглаживания, свечения за контуром, новой палитры или перерисованного большого фонтана.
Улучшения воды: направленное движение бликов в струе, расходящиеся пиксельные кольца, небольшие падающие брызги. Вода остаётся внутри чаши.

ИМПОРТ В UNITY — НЕ ПУТАТЬ С НАБОРОМ ДЕКОРА
У текущего исходного object.fountain.png.meta PPU=40, pivot=(0.5,0.5). Эти значения сохранены.
Не выставлять PPU32 только потому, что у других тайлов игры PPU32: это увеличит фонтан относительно утверждённого оригинала.
Texture Type: Sprite. Sprite Mode: Single для отдельных кадров либо Multiple для общего листа.
Pixels Per Unit=40; Filter Mode=Point; Compression=None; Mipmaps=Off; NPOT Scale=None; Alpha Is Transparency=On; Mesh=FullRect.
Размер нарезки строго 120×120. Не обрезать прозрачные поля и не определять отдельный pivot по непрозрачной области каждого кадра.
Размер изображения в world units до существующего Transform.scale: 3×3. Масштаб объекта оставить как у существующего фонтана.
Rect координаты сверху и Unity Rect снизу перечислены отдельно в manifest.json. Не переворачивать Y дважды.

ВОСПРОИЗВЕДЕНИЕ БЕЗ ШВА
В игровой последовательности только кадры 0...23. Не добавлять второй кадр0 в конец как ещё один удерживаемый кадр: это создаст паузу.
При ручном проигрывании: index = floor(((elapsedSeconds + phaseOffset) mod 2.0) * 12). Менять SpriteRenderer.sprite только при смене индекса.
Для Animator явно проверить длительность 2.0 секунды, частоту12 и Loop Time. Не делать fade-переход между циклами и не интерполировать пиксельные кадры.
Соседство кадров 23→0 является обычным шагом той же периодической анимации. Контрольное состояние при t=2.0 полностью совпадает с t=0.
GIF использует интервалы 80/90/80 мс, суммарно 2000 мс, поскольку GIF хранит время с шагом10 мс. Это ограничение формата превью; игровые PNG проигрывать равномерно при12 fps.
GIF ограничен 256 цветами; в игре использовать PNG/атлас, сохраняющие всю исходную палитру.

СУЩЕСТВУЮЩАЯ ЛОГИКА
Не создавать новый фонтан/коллайдер на каждый кадр. Менять только sprite у существующего объекта.
Сохранить существующую polygon-коллизию MakeSolidLandmark, масштаб fountainScale, взаимодействие, сортировку и освещение.
В DungeonView.MatchWallStone есть коррекция цвета камня через MaterialPropertyBlock. Не сбрасывать её при смене кадра и не умножать весь спрайт на новый синий tint.
Использовать общий материал и заранее загруженные Sprite. Не пересоздавать Texture2D, массивы, материалы или коллайдеры в цикле анимации.
При нескольких фонтанах достаточно общего таймера/менеджера; постоянную фазу можно назначать при спавне. Не менять phaseOffset случайно каждый кадр.
На время вне камеры можно пропускать смену видимого спрайта, сохраняя фазу общего времени.

ПРОВЕРЕНО
24 уникальных кадра; неизменная альфа и размер; исходные цвета; неизменность пикселей вне маски воды.
Контрольная конечная фаза равна первому кадру. Разница на стыке не больше обычных изменений между соседними кадрами.
Исходный файл в проекте не заменялся. Проигрывание, взаимодействие и производительность в Unity необходимо проверить после импорта.
